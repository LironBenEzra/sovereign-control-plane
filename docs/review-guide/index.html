Audit log

        
Every request leaves a chain of signed records in data/audit/audit.jsonl. With three files, anyone outside can check the chain and rebuild every decision, without the server and without the prompt.


        
One request, as it is in the log

        
The “Name + email” request under policy 1.4.0, on a local stack signed by its own key (ed25519:91a2fa3c…), from GET /v1/audit/e713ee05aa254cb69a1d29ac46aa1bae. Each record carries the hash of the one before it. Click a record.

        

        

        


        
Read any record

        

          
FieldWhat it is

          
            
seqPosition in the log: 0, 1, 2… with no gaps. Order comes from here, not from the clock.

            
eventThe step: received, detection, decision, model_call, model_reply, outcome or error; or policy_loaded and policy_changed.

            
audit_idOne ID for all the records of a request.

            
bodyWhat the step recorded. Private values never appear: a keyed hash, or a placeholder.

            
prev_hashThe hash of the record before; 64 zeros for the first record.

            
hashSHA-256 of seq, ts, event, audit_id, body and prev_hash, as canonical JSON.

            
sig, key_idThe Ed25519 signature of hash, and which key made it.

          
        


      


      
      

        
Policy

        
One YAML file, policy/policy.yaml (v1.4.0), read on every request. It tells detection what to look for, picks the action, and limits where a prompt may go.


        
How the policy drives each step

        
    
          
  1. Detect. categories lists what counts as private, such as government_id: [US_SSN, …]. The detectors look only for those types, and detection turns their scores into a label: below 0.35 is noise, 0.6 or more is sure.
    2. 
          
  2. Decide. The rules are checked from the top and the first match wins. A rule tests the categories found (any_category) or the label (label). No match: default_action: block.
    3. 
          
  3. Enforce. The action runs. allow and redact reach only a destination listed in egress.allowed_destinations (anthropic), and response.redact_categories cleans the answer.
    4. 
        


        
Four of its nine rules

        

          
RuleDetection findsEnforcement does

          
            
block-secretsany_category: [secret] → blockAn AWS key: AWS_ACCESS_KEY 0.95, from the pattern rulesNo model is called. The block message comes back (HTTP 200).

            
block-when-detection-failedlabel: [unknown_assume_private] → blockA detector failed or ran out of timeNo model is called. HTTP 503 with Retry-After: an outage, not a decision.

            
keep-regulated-in-boundaryany_category: [government_id, financial, health] → route_sovereignAn SSN: US_SSN 0.85, from PresidioThe local model answers. Nothing leaves the boundary.

            
redact-piiany_category: [pii] → redactA name and an email: PERSON 0.85, EMAIL_ADDRESS 1.00Claude gets <PERSON_1> and <EMAIL_ADDRESS_1>; the real values are put back in its answer.

          
        

        
OrderA prompt with an email and an AWS key matches block-secrets first, so it is blocked, not redacted.

        
ChangesSaved in the Policy tab under a new version, with a signed policy_changed record. A policy that is invalid, or would allow a category holding a credential, is refused (422).

Top 10 design decisions

        
Click a card for why, and what it cost.

        

          
          

            
Why
Patterns and Presidio find values, a local LLM finds meaning. Asking a cloud model would send the data out.
Cost
About a second more per short prompt on a CPU; long text is slow to judge.

          

          
          

            
Why
One file to review, edits apply without a restart, and every decision can be replayed.
Cost
A rule can test only categories and labels.

          

          
          

            
Why
The log never misses an egress that happened or claims one that did not, and a crash shows where it stopped.
Cost
Up to six fsynced writes per request.

          

          
          

            
Why
Editing, deleting or reordering a record breaks the chain, and the signing key cannot be copied.
Cost
One KMS call per record, made under the write lock.

          

          
          

            
Why
Type, position and score are all a replay needs; the prompt is kept as a keyed hash that cannot be brute-forced.
Cost
Whatever the detectors missed is readable in the masked prompt.

          

          
          

            
Why
The pipeline never holds the external client; the gateway checks the action and the allowlist on every send.
Cost
Enforced in code only: the container can still reach the internet.

          

          
          

            
Why
The model works with placeholders, and the caller gets a usable answer with the real values.
Cost
Redaction is only as good as detection.

          

          
          

            
Why
A failed detector blocks the prompt, and a local model that is down never becomes an outside call.
Cost
Availability drops whenever a part fails.

          

          
          

            
Why
Callers know when to retry, and an invalid policy blocks everything instead of enforcing rules nobody vouches for.
Cost
A broken policy stops all traffic until it is fixed.

          

          
          

            
Why
No model sees a secret, and a prompt that talks the LLM out of a finding still gets the other two detectors’ protection.
Cost
It waits for the other two detectors, and a finding covers a whole passage, not one value.

          

        

      


      
      

        
My top 10 changes

        
Claude Code wrote the code, tests and first drafts. I reviewed it and asked for more than forty changes; these are the ten that changed the most, leaving out the interface and small fixes. Click a card for the problem and what changed.

        

          
          

            
Problem
Nothing was recorded when a prompt arrived, a detection that found nothing had no record, and an internal error left no trace.
Changed
One record per step: received, detection, decision, model_call, model_reply, then outcome or error. An internal error returns HTTP 500 with the audit ID.

          

          
          

            
Problem
Orders for the AI, typed or hidden in a pasted email or document, passed through like any text.
Changed
The semantic detector also asks whether a prompt is an injection, and block-prompt-injection stops it before any model. It caught 9 of 9, with no false alarm on 39 others.

          

          
          

            
Problem
Meeting notes or an unannounced launch have nothing a pattern can match, so they were allowed out.
Changed
A third detector asks the local model whether a prompt is confidential business content, and keep-confidential-business-in-boundary keeps it inside.

          

          
          

            
Problem
All three detectors read the raw prompt at the same time, so the local LLM saw the keys and names the rules and Presidio found, although block-secrets says a secret reaches no model.
Changed
Rules and Presidio run first. The LLM reads the prompt with their values masked, as a redact decision sends it, and its findings are mapped back to the original text. If rules or Presidio fails, the LLM does not run.

          

          
          

            
Problem
The signing key was read from Secrets Manager into the server’s memory, so anyone inside the server process could copy it.
Changed
Each record’s hash is signed in AWS KMS with an Ed25519 key that never leaves it (alias/scp-demo-audit). If KMS fails, the request gets a 503 and nothing is written. The hosted log was started again.

          

          
          

            
Problem
Setting block-secrets to Allow was accepted, so a prompt with an AWS key would go to Claude unchanged.
Changed
A save that would allow a category holding a credential (AWS key, private key, token, password) is refused with 422, and the Policy tab names the rule and disables Save. The shipped default is held to the same rule.

          

          
          

            
Problem
When a detector failed or ran out of time, the prompt went to the local model, unchecked.
Changed
Policy 1.4.0 adds block-when-detection-failed: such a prompt is blocked, with HTTP 503 and “Try again later”, because it is an outage, not a decision. A secret found at the same time is still a 200 from block-secrets. The Alerts tab already showed both the failing detector and each request it could not check.

          

          
          

            
Problem
With Presidio down, a request got HTTP 200 and an empty answer, /healthz said ok, and a missing spaCy model started a download from outside.
Changed
HTTP 503 with Retry-After and a message, degraded on /healthz, a chip in the UI. A missing model is reported, never downloaded.

          

          
          

            
Problem
Nothing listed unmatched requests, blocked secrets and injections, withheld answers or a broken policy.
Changed
An Alerts tab (GET /v1/alerts) lists health, policy, security and service problems with the requests behind them, plus rule matches and traffic.

          

          
          

            
Problem
A policy could be changed and saved under the same version, so the audit log showed different policies as one version (1.2.0 three times on the demo).
Changed
The server refuses a version already used by another text and names the next free one; the Policy tab fills it in on Save, so a rule change is saved as 1.3.1.

          

        

      


      
      

        
Run it

        
Hosted: https://sovereign-demo.here · one EC2 instance · external model is Claude Haiku 5.5 · about 6 s per short prompt, 10–40 s when the local model answers

        

          
docker compose up --build   # API and UI on http://localhost:8000
make demo                   # the eight sample requests
make verify                 # chain, signatures, replay of every decision
make tamper-demo            # edits a copy of the log three ways
make eval-semantic          # the local LLM on 48 labelled prompts
make eval-judge             # the same, with Claude as an LLM judge
make check                  # Ruff, Pyright, 148 pytest tests
