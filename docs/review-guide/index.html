Name and version
  • id and version go into every decision record, next to the SHA-256 of this exact text (3bb315f5e958… today), so each decision names the policy it was made under.
  • Read on every request: a saved change applies to the next prompt, with no restart.
  • Each saved change gets its own version. A version already used by another text is refused, and the Policy tab fills in the next free one.
Codepolicy.py:98
What counts as private data
  • A category groups the entity types the detectors find. Rules name categories, never types.
  • Only listed types are looked for: the detectors get this list with every request. LOCATION is left out on purpose.
  • confidential_business and prompt_injection come from the local LLM; the rest from patterns and Presidio.
  • Checked: each type belongs to one category only.
Codepolicy.py:115
How sure is sure
  • A finding below min_score (0.35) is noise and ignored.
  • If every finding left is below confident_score (0.6), the label is uncertain, and rule protect-when-unsure keeps the prompt inside.
  • Checked: confident_score is not below min_score.
Codeclassification.py:11
Ordered rules, first match wins
  • decide() checks the rules from the top. A rule matches when every condition it states holds: at least one of any_category, and one of label.
  • The order is the policy: secrets and injection come before regulated data, so a prompt with an email and an AWS key is blocked, not redacted.
  • A prompt a detector could not check is blocked (block-when-detection-failed), with HTTP 503: an outage, not a decision. One guard no rule can override: after a detection failure, nothing goes out.
  • Checked: rule ids are unique, and every category a rule names exists. A misspelled one would never match, which fails open. No rule may allow a category holding a credential.

When no rule matches
  • The action for a prompt no rule matched.
  • Checked: it must be block or route_sovereign. A default that sends data out is refused.

Who may receive a prompt
  • Default deny. A prompt leaves only if a rule says allow or redact and the destination is listed here.
  • Remove anthropic and every outside call is refused at the gateway, and audited.

How a policy is built and changed

        
    
          
  1. Read. yaml.safe_load, then a strict schema, PolicyDocument, that forbids unknown keys: a typo is an error, not a setting silently ignored. policy.py:162
    2. 
          
  2. Cross-checked. Unique rule ids, one category per type, every named category exists, and a default that keeps data in. policy.py:115
    3. 
          
  3. Stored by hash. Each version is saved as data/policies/<sha256>.yaml; a file named active points to the one in force, read and hash-checked on every request. policy.py:252
    4. 
          
  4. Changed. Anyone can edit a draft in the Policy tab and try it on prompts next to the current policy, with nothing saved and no model called. Saving, in the tab or with PUT /v1/policy, needs the admin token, except on the hosted demo, where editing is open to anyone (SCP_OPEN_POLICY_EDITING) and “Back to the original policy” puts the shipped file back. Each saved change needs its own version: one already stored with a different text is refused, and the tab offers the next free one. Editing policy/policy.yaml changes nothing in force. A signed policy_changed record, listing each change in a sentence, is written before the new version takes effect. pipeline.py:567
    5. 
          
  5. Replayed. decide() is a pure function, so verify.py re-runs every decision against the version its record names.

1 · Pattern rulesExact shapes
Regular expressions for keys, tokens and passwords, each with a fixed score, plus an entropy check for random-looking strings. No model involved.
detection/rules.py · 10 types

                
2 · Presidio + spaCyValues in context
Named-entity recognition for names, and recognizers for emails, phones, IDs, cards and IBANs. Checksums (Luhn, IBAN check digits) reject look-alikes, and words such as “passport” raise the score.
detection/presidio.py · 10 types

                
3 · Local LLM · llama3.2:3bMeaning, with no pattern
Judges whether the text is confidential business content or a prompt injection. Temperature 0 and a JSON schema, inside the boundary. It can only add findings.
detection/semantic.py · 5 types

              

              
    
                
  • Patterns and Presidio read the text first. The LLM reads it after their values are masked, and not at all if one of them fails, so it never sees a key or a name.
    • 
                
  • Findings are added together, never voted on, so one detector cannot cancel what another found.
    • 
                
  • Every finding has a type, position, score and detector. Then come a label, a rule and a reason.

Why an LLM in the decision path is safe
                

                  
    
                    
  • It can only add findings. Fooling it leaves the other two detectors’ protection.
    • 
                    
  • Temperature 0, fixed seed, a JSON schema. Any other answer is an error, and errors fail closed.
    • 
                    
  • It records no reason text, which could quote a secret into the log.
    • 
                    
  • Replay uses the recorded findings, so make verify never calls the model.
    •

Limits
                

                  
    
                    
  • A name the NER model misses leaves on redact or allow.
    • 
                    
  • A false injection flag blocks a prompt.
    • 
                    
  • A prompt too long to judge in 30 s (about 7,500 characters on a laptop, 3,500 hosted) is blocked, and an answer that long is withheld.
    • 
                    
  • English only; no street addresses; LOCATION off (it tags every city).
    • 
                    
  • False positives: “Summarise Hamlet by William Shakespeare” redacts a PERSON (the answer is restored).

    Design decisions
    
        
    Click a card for why, and what it cost.
    
        
    
          
          
    
            
    Why
    A hosted classifier sends the data out. Meeting notes, an unannounced launch or a hidden injection have no pattern. The LLM can only add findings.
    Cost
    About a second more per short prompt on a laptop CPU.
    
          
    

          
          
    
            
    Why
    One place to review, edits apply without a restart, every decision replays.
    Cost
    A rule can test only categories and labels.
    
          
    

          
          
    
            
    Why
    On record from arrival; never claims an egress that did not happen; a failed request shows where it stopped.
    Cost
    Up to six fsynced writes per request instead of two.
    
          
    

          
          
    
            
    Why
    Silently enforcing rules the operator believes they replaced is worse than an outage they notice.
    Cost
    A typo stops all traffic until it is fixed.
    
          
    

          
          
    
            
    Why
    Type, position and score are all a replay needs. A keyed hash, because a plain SHA-256 of an SSN can be brute-forced.
    Cost
    Anything the detectors missed is readable in the masked prompt, and metadata is visible.
    
          
    

          
          
    
            
    Why
    The caller owns the data, so the answer stays usable. The map lives in memory for one request.
    Cost
    Redaction is only as good as detection.
    
          
    

          
          
    
            
    Why
    A sovereign failure must never become an external call.
    Cost
    No failover from the external model to the sovereign one.
    
          
    

          
          
    
            
    Why
    Only detectors and model providers have more than one implementation.
    Cost
    A new kind of step means editing the pipeline.
    
          
    
        
    
      
    

      
      
    
        
    Long-range plan
    
        
    What we would build before this carried real traffic, in order. Click a card for today and the production version.
    

        
    Before real traffic
    
        
    
          
          
    
            
    Today
    Only the egress gateway holds the external model, but the container itself can reach the whole internet.
    In production
    The control plane runs in a private subnet with no route out. The only exit is an egress proxy, or a VPC endpoint, that allows the Claude API host and nothing else. A bug or a compromised dependency has nowhere to send data.
    
          
    

          
          
    
            
    Today
    One EC2 instance runs the control plane, Ollama and Caddy side by side on 2 CPUs. A long local answer can push another request’s detection past its time budget, and a model that runs out of memory can take the gateway down with it. Every container there can reach the instance role, which can sign with the audit key and read the secrets.
    In production
    The model runs on its own GPU nodes in a private subnet, with no internet route and no IAM role. Only the gateway can reach it, over mTLS through an internal load balancer. Detection and answers get separate model pools, so a long answer never starves detection. Each tier scales and fails on its own; if the model tier is down, prompts that must stay inside are blocked, as today.
    
          
    

          
          
    
            
    Today
    No caller authentication: X-Client-Id is recorded as claimed. On the demo anyone can change the policy, and the audit endpoints are open.
    In production
    mTLS or OIDC tokens per client, with the client ID taken from the verified identity. Roles from SSO: caller, policy admin, auditor. Rate limits and quotas per client.
    
          
    

          
          
    
            
    Today
    On the hosted demo anyone can change the policy, so a reviewer can try the whole flow. Every change is a signed record, attributed to a visitor, and the original policy is one click away.
    In production
    Open editing is off. Only policy admins, signed in through SSO, can save a change or put the original back; anyone else can only try a draft. Each change names the admin who made it and goes through the policy change workflow.
    
          
    

          
          
    
            
    Today
    A hash chain signed in KMS. Anyone allowed to sign could still rewrite records that nobody kept a receipt for.
    In production
    Every minute the chain head goes to write-once storage (S3 Object Lock, compliance mode) with an RFC 3161 timestamp. The verifier checks the log against these anchors, so a rewrite shows without receipts.
    
          
    

          
          
    
            
    Today
    Synchronous. The placeholder map is a variable of the request and is gone when it returns. If the external reply does not come back in time, the caller gets a 503 and starts over.
    In production
    A long request returns at once with a request ID. The map is parked in Redis, sealed and with a TTL, and used exactly once when the reply arrives. Keyed by request ID, so one request can never read another’s values.
    
          
    
        
    

        
    To scale and operate
    
        
    
          
          
    
            
    Today
    One process writes the log, and a lock in that process keeps the order.
    In production
    Several instances behind a load balancer, appending through one ordered sequencer: a single-partition stream, or a database write that succeeds only if the head hash has not changed.
    
          
    

          
          
    
            
    Today
    One m7i-flex.large on CPU: 6 to 40 seconds per local answer, and a 30-second detection budget.
    In production
    The model tier from card 2 on GPU instances, or a larger sovereign model. The control plane on ECS or EKS, autoscaled across availability zones.
    
          
    

          
          
    
            
    Today
    The Alerts tab, computed from the log on each refresh, and /healthz.
    In production
    OpenTelemetry metrics and traces, SLOs on latency and on the fail-closed rate, and paging for detector outages, audit write failures and KMS errors.
    
          
    

          
          
    
            
    Today
    deploy/ec2.sh copies the working tree and builds on the server.
    In production
    Terraform or CDK. Images built, scanned and signed in CI, then deployed blue-green through a staging environment. No SSH.
    
          
    
        
    

        
    To broaden
    
        
    
          
          
    
            
    Today
    English only, no address recognizer, and the local LLM measured on 48 labelled prompts.
    In production
    Addresses, more countries’ IDs and other languages. Thousands of labelled prompts run in CI on every detector or prompt change, plus a red-team set for injection.
    
          
    

          
          
    
            
    Today
    On the demo anyone can try a draft and save it, and every change is a signed record; elsewhere one admin token saves it.
    In production
    Only admins can change the policy. It lives in git, with review and two-person approval, tests in CI (prompt in, expected action out), and a shadow period before a change takes effect.
    
          
    

          
          
    
            
    Today
    The signing key is in KMS. The HMAC key and a static Claude API key are in Secrets Manager. A new signing key starts a new log.
    In production
    Rotation with a signed hand-over record that the verifier follows. The HMAC key in KMS. Workload Identity Federation for the Claude API, so no static key exists.
    
          
    

          
          
    
            
    Today
    The whole answer is scanned, then returned.
    In production
    The answer streams in chunks, each scanned and restored before release, with a short window held back so a secret split across two chunks is still caught.
    
          
    

          
          
    
            
    Today
    One policy, one log and one set of keys.
    In production
    A policy, an audit log, keys and quotas per tenant, with isolation between tenants tested.
    
          
    

          
          
    
            
    Today
    The log grows on one disk with no end date, and the external model is Anthropic’s API.
    In production
    A retention policy with archives in S3 Object Lock. Claude served from the region the data must stay in (Amazon Bedrock, or Claude Platform on AWS), a zero-data-retention agreement, and a DPIA.

    Filters by decision, rule and category, applied on the server so paging stays correct. The lists offer the rules and categories found in the log.
    
          
    

          
          
    
            
    Problem
    Clicking a row in the audit log sometimes opened it upward and sometimes downward.
    Changed
    Each request and record opens and closes only on its own click, and the clicked row stays where it is on screen, so content always opens below it.
    
          
    

          
          
    
            
    Problem
    A blocked injection was logged only as <PROMPT_INJECTION_1>, so the attack itself could not be seen.
    Changed
    The masked prompt hides only personal data and secrets, so the injection text stays readable. Confidential business content stays masked.
    
          
    

          
          
    
            
    Problem
    The hosted demo’s audit keys were files on the server’s disk, and no admin token was set.
    Changed
    The signing key, the HMAC key and the admin token are in AWS Secrets Manager (eu-north-1, scp-demo/), read at startup with an instance role that can read nothing else. The server holds no private key.
    
          
    

          
          
    
            
    Problem
    The signing key was read from Secrets Manager into the server’s memory, so anyone inside the server process could copy it.
    Changed
    Each record’s hash is signed in AWS KMS with an Ed25519 key that never leaves it (alias/scp-demo-audit). If KMS fails, the request gets a 503 and nothing is written. The hosted log was started again.
    
          
    

          
          
    
            
    Problem
    The external model was the labelled stub, on the hosted demo and locally, so a reviewer never saw a real answer from outside the boundary.
    Changed
    Prompts the policy lets out go to Claude Haiku 5.5 (claude-haiku-5-5), the smallest Claude model and now the default. The hosted demo reads its API key from Secrets Manager, a local run from .env. A redacted prompt reaches Haiku with placeholders only, and its answer is restored inside the boundary.
    
          
    
          
          
    
            
    Problem
    Enforce showed the answer first and never showed which values were swapped, so it was not clear that the real values came back.
    Changed
    Enforce is numbered 3.1 to 3.4, each step on its side of the boundary: values replaced with placeholders inside, sent and answered outside, values put back inside. Each swapped value is highlighted.
    
          
    
          
          
    
            
    Problem
    Trying a policy edit needed the admin token, so letting a reviewer test the policy meant sending them the master secret. Once open, it was too slow to use: every edit re-ran all 13 prompts, about 85 seconds.
    Changed
    Anyone can edit a draft in the Policy tab and try it on prompts next to the policy in force. Nothing is saved, recorded or sent to a model, and saving still needs the admin token. The table fills in as soon as it opens, and after each edit it updates in about a second, because detection is reused for 10 minutes.
    
          
    
          
          
    
            
    Problem
    Saving a policy change still needed the admin token, so a reviewer could not try the whole flow without being sent it.
    Changed
    On the hosted demo anyone can save the policy, and “Back to the original policy” always puts the shipped one back. Every change is a signed record, attributed to a visitor. In production only admins change it (Long-range plan, card 4).
    
          
    
          
          
    
            
    Problem
    The semantic detector was measured only against 48 hand labels, so a bigger evaluation meant labelling every new prompt by hand.
    Changed
    make eval-judge has Claude label every test prompt with the detector’s own definitions, without seeing its answer, and reports where the judge, the hand labels and the detector disagree, with the judge’s reason. Only the synthetic test prompts are sent.
    
          
    
          
          
    
            
    Problem
    The detection record gave only a count, "findings": 2. Which detector found each one and its score were in the decision record, so the findings were written twice.
    Changed
    The detection record lists every finding once: type, position, score, the detector and recognizer that found it, and counted, whether the decision used it. The decision record no longer copies them, and the verifier replays each decision from the request’s detection record. Older logs still verify.
    
          
    

          
          
    
            
    Problem
    The interface looked flat: grey cards on a grey page, a header that blended into it, and grey charts.
    Changed
    A dark header and tab bar, with each model’s status in its boundary colour. Samples, charts and traffic numbers take the colour of where the prompt ends up, the decision is larger, and before the first prompt a map shows the four steps inside the boundary.
    
          
    
          
          
    
            
    Problem
    The policy still allowed stub-external, a stand-in for running without an API key, although the system uses Anthropic.
    Changed
    The stub is gone from the policy (now v1.2.1), the code and the docs. Without a key the external model reports not ready and nothing leaves the boundary. The sample run, the screenshots and the traces here were recorded again with Claude Haiku 5.5.
    
          
    

          
          
    
            
    Problem
    After changing the detection thresholds there was no way to save: the local stack had no Save button, and on the demo “Save and apply” stayed disabled without saying why.
    Changed
    The local stack allows editing like the demo (SCP_OPEN_POLICY_EDITING=true in .env; the repository default stays off). The cursor goes to the reason box, and until a reason is written the panel says “Write why to save.”
    
          
    

          
          
    
            
    Problem
    The Decide step showed the policy’s SHA-256, a hash that means nothing to someone reading the decision.
    Changed
    The step shows only the policy’s name and version. The hash is still in every decision record, where the verifier uses it.
    
          
    

          
          
    
            
    Problem
    All three detectors read the raw prompt at the same time, so the local LLM saw the keys and names the rules and Presidio found, although block-secrets says a secret reaches no model.
    Changed
    Rules and Presidio run first. The LLM reads the prompt with their values masked, as a redact decision sends it, and its findings are mapped back to the original text. If rules or Presidio fails, the LLM does not run.
    
          
    

          
          
    
            
    Problem
    The audit did not keep the model’s answer. It counted the values put back and the types removed from the answer, but not which values or where.
    Changed
    A new model_reply record, written before the answer is returned, keeps the answer as it came back with private values masked, what the scan found and what was redacted again. An answer from the local model is not kept, only its length and findings. The outcome names the placeholders put back.
    
          
    
          
          
    
            
    Problem
    The answer scan removed only secrets. The local LLM never read a model’s answer, so confidential business content in it came back as it was.
    Changed
    Policy 1.3.0 adds confidential_business to response.redact_categories. The local LLM judges every answer and replaces a confidential passage with a placeholder; if it fails or runs out of time, the answer is withheld.
    
          
    
          
          
    
            
    Problem
    Detection had 15 seconds by default, and the local LLM now judges every answer too. Measured on the laptop, 7,500 characters took 22 s, so a long prompt was treated as private and a long answer withheld.
    Changed
    The default is 30 seconds, as the hosted demo already had, for the prompt and again for the answer. 7,500 characters are now judged; 10,000 (35 s) are not.
    
          
    
          
          
    
            
    Problem
    A policy could be changed and saved under the same version, so the audit log showed different policies as one version (1.2.0 three times on the demo).
    Changed
    The server refuses a version already used by another text and names the next free one; the Policy tab fills it in on Save, so a rule change is saved as 1.3.1.
    
          
    
          
          
    
            
    Problem
    A rule change showed in the YAML but not in the Rules on the Policy tab.
    Changed
    policy.yaml no longer says an edit to it takes effect: the policy changes in the Policy tab or API, and the file is what “Back to the original policy” puts back. The page is sent with Cache-Control: no-cache, so a browser never keeps an old build.
    
          
    
          
          
    
            
    Problem
    The Model reply step listed what the scan found in the answer, but not whether the response rules changed it, or why not. A health finding there looked like enforcement that never happened.
    Changed
    The signed model_reply record now has a rationale: “The scan found HEALTH_CONTEXT (health), but the response rules remove only secret and confidential_business, so the answer is unchanged.” The Audit log shows it under Answer unchanged or Answer changed, and the rule’s reason under the Decision step.
    
          
    
          
          
    
            
    Problem
    The Alerts tab checked the audit log again only when its size or modification time changed. An edit that kept the size and set the time back stayed “intact” until the next record was written.
    Changed
    It now checks again when the SHA-256 of the log, the public key or a policy snapshot changes. Hashing takes milliseconds; the signatures are checked again only when something changed.
    
          
    
          
          
    
            
    Problem
    For a prompt that reached no model, the Playground showed the reason code, blocked_by_policy, but not the message the caller gets back. Two labels were also wrong: a local model that was down showed as “No model was called”, and a withheld answer from Claude as “No answer came back”.
    Changed
    The Enforce step now adds Returned to you with the message: “This request was blocked by the data protection policy. No model was called.” A model that is down shows as called and not answering, and a withheld answer as “An answer came back, but scanning it failed, so it was withheld”.
    
          
    
          
          
    
            
    Problem
    Setting block-secrets to Allow was accepted, so a prompt with an AWS key would go to Claude unchanged.
    Changed
    A save that would allow a category holding a credential (AWS key, private key, token, password) is refused with 422, and the Policy tab names the rule and disables Save. The shipped default is held to the same rule.
    
          
    
          
          
    
            
    Problem
    When a detector failed or ran out of time, the prompt went to the local model, unchecked.
    Changed
    Policy 1.4.0 adds block-when-detection-failed: such a prompt is blocked, with HTTP 503 and “Try again later”, because it is an outage, not a decision. A secret found at the same time is still a 200 from block-secrets. The Alerts tab already showed both the failing detector and each request it could not check.
    
          
    
          
          
    
            
    Problem
    The logo, a dashed square with a red dot, did not say what the product does.
    Changed
    A shield split by a dashed line: purple on the left for inside the boundary, blue on the right for outside, the colours those sides have everywhere in the UI. The browser tab icon is the same shield.
